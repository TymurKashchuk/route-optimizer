# RouteWise

Вебзастосунок для планування поїздок зі стартом, фінішем і до 10 проміжних зупинок.

RouteWise використовує евристичні алгоритми для пошуку порядку відвідування зупинок із меншим часом у дорозі, порівнює результат із початковим маршрутом, показує його на карті та формує розклад прибуття й відправлення.

## Швидкий старт

Для запуску через Docker Compose:

```bash
# Клонувати репозиторій
git clone [https://github.com/TymurKashchuk/route-optimizer.git](https://github.com/TymurKashchuk/route-optimizer.git)
cd route-optimizer

# Створити файл змінних середовища
cp .env.example .env

# Зібрати та запустити сервіси
docker compose up --build -d
```

Після запуску:
- Вебзастосунок: http://localhost:5173
- API: http://localhost:5044

> Без API-ключа застосунок використовує демонстраційні провайдери. Для розрахунків за реальною дорожньою мережею вкажіть ключ OpenRouteService у `.env`. Демонстраційний режим не є повноцінним офлайн-режимом.

## Можливості

### Планування маршруту

- Фіксовані точки старту (A) та фінішу (B), до 10 проміжних зупинок.
- Індивідуальний час перебування на кожній зупинці: від 0 до 480 хвилин.
- Ручна зміна порядку зупинок перетягуванням.
- Три способи пересування: авто (`driving`), пішки (`walking`) та велосипед (`cycling`).

### Алгоритми впорядкування

- `original` — порядок зупинок, заданий користувачем.
- `nearest-neighbor` — послідовний вибір наступної зупинки з найменшим часом переїзду.
- `two-opt` — локальне покращення маршруту через зміну порядку сегментів для зменшення загального часу в дорозі.

Застосунок порівнює отриманий маршрут із початковим порядком і показує різницю в часі та відстані. Евристичні алгоритми не гарантують глобально оптимального результату.

### Планування за часом

- «Виїхати о…» (`depart-at`) — розрахунок прибуття й відправлення для кожної точки на основі заданого часу виїзду.
- «Прибути до…» (`arrive-by`) — розрахунок рекомендованого часу виїзду для прибуття до заданого дедлайну.

### Адресний пошук і карта

- Автокомпліт адрес через OpenRouteService / Pelias із пошуком по Україні або в межах обраного міста.
- Визначення поточного місцезнаходження через браузерну геолокацію та зворотне геокодування.
- Інтерактивна карта Leaflet із маркерами старту, фінішу та пронумерованих зупинок.
- Відображення маршруту за дорожньою мережею при використанні OpenRouteService.
- Додавання старту, фінішу та проміжних зупинок кліком по карті.
- Відкриття маршруту в Google Maps і копіювання відповідного посилання.

### Збереження стану та теми

- Автоматичне збереження чернетки поїздки в `localStorage`.
- Підтримка світлої та темної тем.

### Демонстраційний режим

Без API-ключа використовуються вбудовані адреси та наближені відстані за формулою гаверсинуса. Час у дорозі оцінюється за фіксованою швидкістю відповідного транспорту.

Демонстраційні розрахунки не враховують реальну дорожню мережу.

## Конфігурація

Для запуску через Docker Compose параметри задаються у файлі `.env`. Шаблон конфігурації — `.env.example`.

| Змінна | Опис | За замовчуванням |
|---|---|---|
| `OPENROUTE_SERVICE_API_KEY` | Ключ OpenRouteService | Порожнє значення — демонстраційний режим |
| `ASPNETCORE_ENVIRONMENT` | Середовище ASP.NET Core: `Production` або `Development` | `Production` |
| `ENABLE_SWAGGER` | Увімкнення Swagger UI в контейнері: `true` або `false` | `false` |

Ключ OpenRouteService можна отримати в [кабінеті розробника](https://openrouteservice.org/dev/#/signup).

## Локальна розробка

Потрібні:
- .NET 8 SDK
- Node.js 22+

### Бекенд

Запуск із кореня репозиторію:

```bash
dotnet run --project RouteWise.Api --launch-profile http
```

API: http://localhost:5044

Swagger UI доступний за адресою http://localhost:5044/swagger, якщо його ввімкнено для поточного середовища.

Для збереження API-ключа в локальних .NET User Secrets:

```bash
dotnet user-secrets set "OpenRouteService:ApiKey" "<ваш_ключ>" --project RouteWise.Api
```

### Фронтенд

```bash
cd frontend
npm ci
npm run dev
```

Вебзастосунок: http://localhost:5173

У режимі розробки запити до `/api` проксуються на бекенд за адресою `http://localhost:5044`.

## Архітектура

Бекенд розділяє отримання географічних даних, оптимізацію порядку зупинок і розрахунок результатів:

- `Providers` — геокодування та отримання даних маршрутизації через OpenRouteService або демонстраційні реалізації.
- `Optimizers` — вибір порядку відвідування зупинок.
- `Services` — виконання сценарію планування, розрахунок метрик, розкладу та прев’ю маршруту.
- `Validators` — перевірка вхідних даних.
- `Middleware` — централізована обробка помилок.

На фронтенді UI-компоненти відокремлені від API-клієнтів, утиліт і повторно використовуваної логіки в хуках.

### Структура проєкту

```text

│   ├── Models/               # Внутрішні моделі

│   ├── Optimizers/           # original, nearest-neighbor, two-opt
```

## Обмеження

- Точність адресного пошуку залежить від покриття даних геокодування. Для деяких адрес результат може відповідати вулиці, а не конкретній будівлі.
- Перед поїздкою перевіряйте розташування точок на карті. Маршрут також можна відкрити в Google Maps.
- Демонстраційний режим використовує наближені розрахунки без урахування дорожньої мережі та не є повноцінним офлайн-режимом.
- Евристичні алгоритми не гарантують глобально оптимального порядку зупинок.
- Доступність зовнішніх сервісів і квоти OpenRouteService можуть обмежувати виконання запитів.
